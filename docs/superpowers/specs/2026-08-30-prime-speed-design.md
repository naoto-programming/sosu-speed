# 素数スピード — 設計書

## 概要

2人対戦のブラウザカードゲーム。場に置かれた合成数を素因数分解し、対応する素数カードを出していく。自分の山札の最後（Stopカード）を引いた方が勝ち。

技術スタックはプレーンな HTML / CSS / JS（ビルド不要、フレームワーク不使用）。既存の空ファイル `index.html` / `style.css` / `game.js` を実装する。ビジュアルは `nabla-game-master` の配色・フォント・ボタンスタイルを踏襲するが、カード描画は Canvas ではなく HTML/CSS の角丸カード要素で行う。

## 定数

```js
const PRIMES = [2, 3, 5, 7, 11];
const DEFAULT_MAX_COMPOSITE = 1100;
const DEFAULT_COUNT_PER_PRIME = { 2: 6, 3: 6, 5: 6, 7: 6, 11: 6 };
const HAND_SIZE = 5;
```

## 配色・スタイル（nabla-game-master 準拠）

- `--color-dark: #232248`（濃紺）／ `--color-light: #fffcf9`（クリーム）
- 見出しフォント: `'Roboto Slab'`（Google Fonts）
- ボタン: クリーム背景・濃紺3px枠・角丸5px・太字。`:active` で色反転
- カード: クリーム背景・濃紺2〜3px枠・角丸8〜10px・中央に大きな数字。box-shadowで軽い浮き上がり

## 画面構成

1. **タイトル画面** (`#screen-title`): タイトル、「対戦開始」ボタン、「設定」ボタン
2. **設定画面** (`#screen-settings`): 素数ごとの山札枚数（2,3,5,7,11 それぞれ数値入力）、合成数の最大値（数値入力、デフォルト1100）、「デフォルトに戻す」「対戦開始」ボタン
3. **ゲーム画面** (`#screen-game`): 詳細は下記
4. **ゲーム終了画面** (`#screen-gameover`): 勝者表示、「もう一度」ボタン

### ゲーム画面レイアウト

- 上部: プレイヤー2の手札（5枚、カード）＋ 山札残り枚数
- 中央: 現在の合成数（大きく表示）／ 残り必要な素因数の内訳（例: `2×1 3×1 5×1` のようなチップ表示、出すたびに減る）
- 下部: プレイヤー1の手札（5枚、カード）＋ 山札残り枚数
- 両プレイヤーの手札は常に表向き（同一画面を共有するローカル対戦のため、相手の手札を隠す機構は設けない）

## データモデル

```js
Player {
  hand: number[]        // 手札の値の配列（5枚）
  deck: (number|'STOP')[]  // 山札。末尾が必ず'STOP'
}

GameState {
  players: [Player, Player]
  composite: number          // 現在場にある合成数
  remaining: { [prime]: count }  // 残り必要な素因数の枚数
  previousComposite: number | null
  compositePool: number[]    // 起動時に列挙した「出現しうる合成数」の全リスト
  winner: 0 | 1 | null
}
```

## ロジック

### 山札生成

各プレイヤーごとに独立に：
1. 設定枚数分の素数カード配列を作る（例: 2が6枚, 3が6枚...）
2. Fisher-Yatesでシャッフル
3. 配列の末尾に `'STOP'` を1枚追加（シャッフル対象外、常に最後）
4. 先頭 `HAND_SIZE` 枚を手札として取り出す（`splice(0, 5)`）

### 合成数プールの列挙

起動時（または設定変更時）に一度だけ計算：

```js
function enumerateComposites(max) {
  const pool = [];
  for (let n = 4; n <= max; n++) {
    const factors = factorizeWithAllowedPrimes(n, PRIMES); // 2,3,5,7,11だけで割り切れるか試し割り
    if (factors && sumCounts(factors) >= 2) pool.push(n); // 素数自身(1個の素因数)と1は除外
  }
  return pool;
}
```

これにより場に出る合成数は必ず現在のルールの素数カードだけで分解可能になる（デッドロック防止）。

### 次の合成数を選ぶ

`compositePool` から `previousComposite` と異なる値をランダムに1つ選ぶ。選んだら `remaining` をその値の素因数分解結果（例: 60 → `{2:2, 3:1, 5:1}`）で初期化する。

### カードを出す（クリックハンドラ）

1. クリックされたカードの値 `v` について `remaining[v] > 0` かを確認。0以下なら何もしない
2. 手札から該当カードを1枚取り除き、`remaining[v]` を1減らす
3. 自分の山札の先頭から1枚引いて手札に加える（5枚に戻す）
   - 引いた札が `'STOP'` の場合: 即座にそのプレイヤーの勝利として `winner` を確定し、ゲーム終了画面へ
4. `remaining` の全値が0になったか判定 → クリア済みなら次の合成数を選ぶ（`previousComposite` を今引いた値に更新）
5. クリアしていなければ「膠着判定」を行う（下記）

### 膠着判定（詰み）

出す/引くイベントの後、`remaining` に残りがある状態で、両プレイヤーの手札のどのカードも `remaining[v] > 0` を満たさない（＝どちらも出せる手がない）場合、現在の合成数を強制的に破棄し、次の合成数を選ぶ。

### 勝利条件

いずれかのプレイヤーが自分の山札から `'STOP'` を引いた瞬間、そのプレイヤーの勝利で即終了。

## エッジケース

- 設定で合成数の最大値を小さくしすぎて `compositePool` が空になる場合: 入力に `min="4"` を設け、空になった場合は最大値を自動的に必要最小値まで引き上げる（アラート表示）
- 山札枚数設定を0にした素数がある場合: その素数は合成数の分解結果に出現しても手札・山札のどこにも存在しないため詰み判定が正しく機能する（膠着扱いになるだけで壊れない）
